Flame: a distributed engine for AI workloads

Flame helps teams run elastic AI workloads across distributed infrastructure. It brings sessions, task scheduling, executor reuse, object caching, and secure runtime isolation into one runtime for agents, reinforcement learning, generated-code execution, and more.

Get Started View on GitHub

What Flame Provides

Scale

Run many short-lived tasks across multiple nodes while keeping resource sharing fair across tenants and sessions.

Performance

Reuse executors inside sessions, reduce startup overhead, and improve throughput for elastic task-heavy workloads.

Security

Use session-dedicated runtime environments and mTLS between Flame components to reduce data leakage risk.

Runner API

Package Python projects and expose functions, classes, or instances as remote services with flamepy.runner.

Object Cache

Share common data, Runner contexts, and incremental object updates without repeatedly copying full payloads.

Flexible Services

Integrate applications through gRPC and service shims, with support for Rust, Go, Python, and more.

How Flame Works

A Flame session groups related tasks. The session scheduler allocates resources, executors connect back to Flame over gRPC, and services pull work for the session they are bound to. Executors can be reused while the session is active, which is especially useful for agents and reinforcement-learning workloads that issue many small tasks.

Core Concepts

  • Session: A group of related tasks with scheduling, resource, and isolation boundaries.
  • Task: A unit of work submitted by a client and executed by a service in an executor.
  • Executor: A runtime environment that hosts application services for a session.
  • Object cache: A shared data layer used by Runner, common data, and incremental object updates.
